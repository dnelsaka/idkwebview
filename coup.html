1 · Environment / bridge probe

Confirms the page runs inside the privileged WebView and which native JS bridges are exposed to this (attacker) origin.

2 · JS bridge → "CoupangPlay" (ec.d)

Input bridges reachable from any loaded origin. webviewCallback drives native navigation / token-consent refresh.

3 · JS bridge → "playWebTrackingHandlers" (C6854c)

Second bridge attached to every page. Probe its methods (auto-enumerated below).

4 · Launch NON-EXPORTED components (intent:// pivot)

The WebViewClient runs Intent.parseUri()+startActivity() with no component sanitization, so page navigation can start the app's own non-exported activities with attacker extras.

5 · Fire internal coupangplay:// deep links (handlePlayScheme)

The WebViewClient executes app deep links requested by the page — attacker web content can drive any in-app route.
